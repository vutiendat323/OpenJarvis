1. Sơ đồ Luồng Hoạt động Tổng thể (End-to-End Flow)

Hệ thống Customer Display là kênh hiển thị trực quan thứ hai (Secondary Visual Channel) hoạt động song song với kênh Giọng nói (Voice/WebRTC). Nó cho phép khách hàng nhìn thấy món gợi ý, giỏ hàng, hóa đơn và quét mã VietQR trong khi đang nói chuyện với Agent.

2. Bộ 5 Công Cụ `display_*` trong Backend

Được định nghĩa tại src/openjarvis/tools/display.py, mỗi tool chịu trách nhiệm cho một giao diện hiển thị chuyên biệt:

Tên Tool Mục đích Tham số yêu cầu View hiển thị trên UI
display_menu Gợi ý 2–3 món cho khách items: [{id, name, price, available, note}] view: "menu" (Thực đơn thẻ đôi)
display_cart Hiển thị giỏ hàng đang chọn lines: [{name, size, note, quantity, line_total}], total view: "cart" (Danh sách món + Tổng tiền)
display_bill Hiển thị hóa đơn chính thức sau chốt đơn order_id, status, order_type, branch, lines, total view: "bill" (Hóa đơn chi tiết)
display_payment_qr Hiển thị mã VietQR động để thanh toán order_id, payment_slug, status, qr_code view: "payment_qr" (Mã QR thanh toán ngân hàng)
display_clear Đưa màn hình về trạng thái chờ Không có view: "waiting" (Sẵn sàng phục vụ)

3. Máy Trạng Thái Giao Diện (UI State Transitions)

Giao diện React quản lý trạng thái hiển thị thông qua bộ Reducer nghiêm ngặt tại frontend/src/pages/customerDisplayState.ts:

stateDiagram-v2 [*] --> Waiting : Khởi động / display_clear Waiting --> Menu : display_menu Menu --> Cart : display_cart Menu --> Menu : Cập nhật món mới Cart --> Cart : Sửa số lượng / size / ghi chú Cart --> Bill : display_bill (Đã chốt đơn) Bill --> PaymentQR : display_payment_qr (Yêu cầu thanh toán) PaymentQR --> Waiting : display_clear (Xong phiên) Bill --> Waiting : display_clear Cart --> Waiting : display_clear

1. View: Menu

Lưới thẻ món đồ uống 2 cột sang trọng, kèm giá tiền, ghi chú hương vị và badge hết hàng.

2. View: Cart

Danh sách các món khách đã chọn, số lượng, size, ghi chú riêng từng ly và tổng tiền tạm tính.

3. View: Bill

Mã đơn hàng từ hệ thống POS, chi nhánh, hình thức (Mang đi / Tại quán) và bảng chi tiết.

4. View: Payment QR

Render mã VietQR động (base64 image hoặc URL) bo tròn trên khung nền trắng nổi bật cho khách quét.

4. Chi tiết 4 Bước Xử Lý Kỹ Thuật (Technical Breakdown)

Bước 1: Lọc dữ liệu an toàn tại Tool (`_picked`)

Hàm _picked trong display.py loại bỏ mọi trường lạ hoặc mã độc LLM có thể sinh ra:

_ITEM_FIELDS = ("id", "name", "price", "available", "image_url", "note")
_LINE_FIELDS = ("name", "size", "note", "quantity", "line_total")
_PAYMENT_QR_FIELDS = ("order_id", "payment_slug", "status", "qr_code")

def _picked(row: Any, fields: tuple[str, ...]) -> dict[str, Any]:
    if not isinstance(row, dict): return {}
    return {key: row[key] for key in fields if key in row}

Bước 2: Quản lý Phiên hiển thị (`PresentationSessionManager`)

Đảm bảo event được gắn đúng session_id và loại bỏ các publication cũ bị trễ (Stale Generation Guard):

normalized = deepcopy(payload)
normalized["presentation_session_id"] = self._session.session_id
self._session.last_payload = normalized
self._bus.publish(EventType.DISPLAY_UPDATE, normalized)

Bước 3: Cầu nối WebSocket truyền phát tức thì (`ws_bridge.py`)

FastAPI WebSocket endpoint đẩy gói tin JSON thời gian thực tới màn hình phụ:

{
  "type": "display_update",
  "timestamp": "2026-08-26T01:55:00.000Z",
  "data": {
    "view": "payment_qr",
    "presentation_session_id": "7a8b9c...",
    "order_id": "740b72fd33",
    "payment_slug": "78d97744f8",
    "status": "pending",
    "qr_code": "data:image/png;base64,iVBORw0KGgo..."
  }
}

Bước 4: React UI Render trong dưới 50ms (`CustomerDisplayPage.tsx`)

Hook useAgentEvents nhận stream WebSocket, Reducer kiểm tra khớp sessionId và render thẻ React tương ứng tức thì.

5. Điểm Ưu Việt của Kiến Trúc này

  • Phân tách hoàn toàn (Decoupled): Backend chỉ truyền dữ liệu cấu trúc (JSON). Toàn bộ giao diện, hiệu ứng chuyển động và responsive do React đảm nhiệm.
  • Thời gian thực (Real-time < 50ms): Khách hàng nhìn thấy thông tin ngay khi Agent vừa quyết định hiển thị, không có độ trễ tải trang.
  • An toàn tuyệt đối: Chống XSS qua _picked, chống stale session qua publication_generation, và chống giả mạo QR qua ToolEvidence.
