OpenJarvis-v2: Kiến Trúc Hệ Thống, Skills, Memory & Learning

Tài liệu phân tích chuyên sâu toàn bộ mã nguồn src/openjarvis, luồng dữ liệu end-to-end, cơ chế nạp Skills, hệ thống Memory bất đồng bộ, pipeline Learning tự động và cơ chế bảo vệ HTTP runtime.

1. Tổng Quan Kiến Trúc (High-Level Architecture)

Hệ thống vận hành theo mô hình Direct-First Agentic Runtime kết hợp đồng thời Text SSE, Voice WebRTC, Computer Vision GPU, và điều khiển màn hình phụ của khách hàng qua Playwright MCP.

2. Cơ Chế Tải và Nạp Kỹ Năng (Skills Loading & Discovery)

Hệ thống Skills cho phép đóng gói quy trình phức tạp thành các chuỗi bước gọi tool (SkillStep) hoặc hướng dẫn markdown có chữ ký bảo mật.

flowchart TD
    Disk["Thu muc Skills (/skills hoac ~/.config/openjarvis/skills)"] --> Loader["Loader: discover_skills()"]
    Loader --> Parser["SkillParser (Doc YAML Frontmatter & Markdown / TOML)"]
    Parser --> SecScan["Security Check (Chu ky verify_b64 & SecretScanner)"]
    SecScan --> Reg["SkillRegistry (Dang ky vao bo nho he thong)"]
    Reg --> Mgr["SkillManager & tool: skill_manage"]
    Mgr --> Agent["Orchestrator Agent (Thuc thi chuoi tool tu dong)"]

Chi tiết triển khai Skills:

  • Định dạng hỗ trợ (loader.py):
    • SKILL.md: YAML frontmatter (name, description, required_capabilities) + nội dung markdown.
    • skill.toml: Khai báo có cấu trúc danh sách [[skill.steps]] với tool_name, arguments_template, output_key.
    • Sourced layout: Phân cấp theo namespace nguồn <dir>/<source>/<name>/SKILL.md.
  • Bảo mật: Tự động quét phát hiện prompt injection qua SecretScanner và kiểm chứng chữ ký mật mã (verify_b64).
  • Thực thi: Công cụ skill_manage cho phép Agent liệt kê hoặc replay tự động chuỗi gọi tool.

3. Kiến Trúc Bộ Nhớ Dài Hạn (Memory Architecture)

Chịu trách nhiệm trích xuất và ghi nhớ các sự kiện lâu dài (sở thích, quy ước) trên luồng nền mà không làm chậm thời gian phản hồi của Agent.

sequenceDiagram
    autonumber
    actor User as Nguoi Dung
    participant Server as Chat API / CLI
    participant Queue as Memory Queue (max 256)
    participant Worker as Background Worker (MemoryService)
    participant Extractor as FactExtractor (LLM chat loc)
    participant Store as LocalFactStore (memory_facts.jsonl)

    User->>Server: Gui tin nhan ("Toi thich uong ca phe it da")
    Server->>Server: Tra loi phan hoi ngay lap tuc cho nguoi dung
    Server->>Queue: submit(user_text, assistant_text) (Non-blocking)
    Note over Queue,Worker: Chay nen tren luong Daemon rieng (Out-of-band)
    Worker->>Queue: Lay cap hoi thoai ra xu ly
    Worker->>Extractor: Trich xuat su that ben vung (Fact Extraction)
    Extractor-->>Worker: ["Khach hang thich ca phe it da"]
    Worker->>Store: Atomic append vao memory_facts.jsonl

Chi tiết kỹ thuật Memory:

  • Out-of-band Worker (service.py): MemoryService chạy luồng Daemon riêng. Hàm submit() đẩy vào hàng đợi non-blocking để API trả lời người dùng tức thì.
  • Trích xuất thông tin (extractor.py): FactExtractor lọc bỏ câu chào ngắn hạn, chỉ giữ lại các fact bền vững có giá trị lâu dài.
  • Lưu trữ an toàn (store.py): LocalFactStore lưu append-only JSONL tại ~/.config/openjarvis/memory_facts.jsonl với cơ chế ghi atomic (file tạm + rename) và khóa threading.Lock().

4. Hệ Thống Tự Học & Tiến Hóa (Learning Pipeline)

OpenJarvis tự động tiến hóa qua 2 cơ chế: Turn-Learning tức thì và Vòng lặp Huấn luyện Tiến hóa định kỳ.

flowchart TD
    subgraph TurnLearning["1. Turn-Learning (Hoc Tuc Thi)"]
        TraceEvt["Su kien TRACE_COMPLETE"] --> TurnWorker["Worker Background"]
        TurnWorker --> SkillDisc["SkillDiscovery: Tham so hoa Trace"]
        SkillDisc --> AutoSkill["Tao Skill Replayable moi (skill_manage)"]
    end

    subgraph BatchLearning["2. Batch Learning Loop (Tien Hoa Dinh Ky)"]
        Traces["TraceStore (Lich su hoi thoai)"] --> Miner["TrainingDataMiner (Loc SFT & Routing dat diem cao)"]
        Miner --> RustICL["Rust ICL Policy (Kham pha chuoi tool lap lai)"]
        Miner --> Evolver["AgentConfigEvolver (Toi uu Prompt & Config)"]
        Miner --> LoRA["LoRA Fine-Tuning (Khi co du >= 10 SFT pairs)"]
        Evolver --> Gatekeeper{"Eval Gatekeeper (eval_fn)"}
        LoRA --> Gatekeeper
        Gatekeeper -->|Diem tang >= 2%| Accept["Ap Dung Ban Cap Nhat Moi"]
        Gatekeeper -->|Diem giam / khong doi| Rollback["Tu Choi / Rollback"]
    end

Chi tiết các giai đoạn Learning:

  • Turn-Learning (learning_orchestrator.py): Lắng nghe EventType.TRACE_COMPLETE. Ngay khi một phiên giao dịch hoàn thành xuất sắc, SkillDiscovery tự động tham số hóa chuỗi lệnh để tạo thành Skill có thể chạy lại ngay lập tức.
  • Rust ICL Pattern Discovery (icl_updater.rs): Thuật toán n-gram tối ưu trên Rust phát hiện các chuỗi gọi tool phổ biến.
  • Kiểm soát chất lượng (Gatekeeper): Đánh giá hiệu năng trước/sau qua eval_fn(); chỉ chấp nhận cập nhật khi điểm số cải thiện tối thiểu 2% (ngăn chặn suy thoái mô hình).

5. Quản Lý Phạm Vi Hội Thoại & Cô Lập State

Cơ chế ContextVar: _CONVERSATION_ID quản lý phạm vi phiên làm việc. Khi Agent thực thi tool song song qua ThreadPool, context được sao chép nguyên vẹn qua contextvars.copy_context().run(...).

Pure ASGI Middleware: Chạy bao trùm toàn bộ chu trình StreamingResponse, đảm bảo tool execution diễn ra sau khi router return vẫn thuộc đúng conversation scope.

Header X-OpenJarvis-Conversation: Tự động tiêm vào response header tại http.response.start, tự động cấp UUID4 mới nếu client gửi ID lạ nhằm chống đọc trộm evidence.

6. HTTP Hardening & Mutation Deduplication

Ngăn chặn việc gửi lặp đơn hàng khi model retry hoặc mạng chập chờn:

sequenceDiagram
    autonumber
    actor User as Khach Hang / Agent
    participant HttpTool as HttpRequestTool
    participant Evidence as Mutation Claim Ledger
    participant Shop as TrendCoffee API

    User->>HttpTool: POST /orders/public (Don hang)
    HttpTool->>Evidence: claim_mutation(method, url, body)
    alt Da ton tai fingerprint trong session
        Evidence-->>HttpTool: allowed = false (response_seen / ambiguous)
        HttpTool-->>User: Refusal (Chan goi mang lap lai)
    else Lan dau goi trong session
        Evidence-->>HttpTool: allowed = true (in_flight)
        HttpTool->>Shop: Gui HTTP POST request
        alt Thanh cong (HTTP 200/201)
            Shop-->>HttpTool: Order Created Data
            HttpTool->>Evidence: finish_mutation(response_seen)
            HttpTool-->>User: Ket qua thanh cong
        else Timeout / Mat ket noi
            Shop--xHttpTool: Connection Timeout
            HttpTool->>Evidence: finish_mutation(ambiguous - Block repeat)
            HttpTool-->>User: Ambiguous Error (Khong retry)
        else Loi mang truoc khi toi Server
            HttpTool->>Evidence: finish_mutation(not_sent - Release)
            HttpTool-->>User: Error (Cho phep retry)
        end
    end

7. Result Projection — Thu Gọn Ngữ Cảnh Tool (21.3x)

Tỉ lệ nén 21.3x: Danh mục menu 106.903 ký tự (~26.700 tokens) được thu gọn xuống còn 5.027 ký tự (~1.256 tokens) trước khi đưa vào LLM transcript.

Toàn vẹn 100% Evidence gốc: ToolEvidence trong RAM vẫn lưu trữ toàn vẹn JSON gốc để các tool display_payment_qr hoặc last_result() trích xuất chính xác mã QR base64 và Order ID.

9. Phân Tích Hiện Tượng "Xin Chào" Bị Treo Hiện Tại

⚠️ Nguyên Nhân Kỹ Thuật Gây Treo "Generating..."

Khi khách hàng nói hoặc gõ "xin chào", Agent được hướng dẫn chuẩn bị thông tin menu bằng cách gọi API:

GET https://trendcoffee.net/api/latest/branch
GET https://trendcoffee.net/api/latest/catalogs

Tuy nhiên, máy chủ gốc của trendcoffee.net hiện đang sập (Cloudflare Error 522: Connection Timed Out). Mỗi request phải đợi Cloudflare hết thời gian chờ (20–60 giây), khiến giao diện chat bị kẹt ở trạng thái Generating.
